## Evidence

**1.1 — the arithmetic.** 18 tests on `simulate.ts`. `frames` covers a depth that fits, one that does not, the exact boundary (10,000 fits, 10,001 does not), zero and negative depths, and sanity checks that V8's default holds thousands of frames rather than millions. `deliver` covers 0 % loss (both lanes complete, no stalls), 100 % loss (UDP delivers nothing, TCP delivers everything), the same seed producing an identical run twice, different seeds producing different runs, TCP arriving complete but with a **later** `newestAgeMs` than UDP at the same loss, UDP never stalling, and its arrivals staying ordered and duplicate-free. One typecheck failure taught something: `STACK_BYTES` is `as const`, so `STACK_BYTES.node` is the literal type `1000000` and narrowed the parameter to it — annotating `stackBytes: number` was the fix.

**1.2 — the sequence.** 12 tests on `content.ts`. Beyond "starts and ends empty", the suite asserts the stack **only ever changes at the top, one frame at a time**, and that frames below never reorder — a stack that reordered would teach the wrong thing. It also pins the four function names to the real call path (`placeMarketOrder`, `toValidOrderSize`, `toChainUnits`, `floorToLot`), so the sequence cannot drift from the code it claims to trace.

**2.1 — memory visualiser.** Stepped in the browser: `1 / 10` with both sides empty → `10 / 10` with the stack empty and the heap still holding `markets: Market[]`, marked unreachable. Nine steps back restored the initial state exactly, and Back at step 1 is a no-op.

**2.2 — depth slider.** Depth 5,000 recursive → "Fits." Depth 40,000 recursive → "Stack overflow" with both real error strings. Iterative at the maximum → "Fits. A loop keeps one frame on the stack however long the input is." Copy-loop variant → the copy-trade framing of the same failure. It never recurses: `frames()` answers from arithmetic (design D3).

**2.3 — packet race.** At 0 % loss both lanes read `arrived 12/12 · newest is 0 ms old`. At 40 %, with the same seed so both lose the same packets: TCP `12/12 · newest is 840 ms old · stalled 7×`, UDP `5/12 · newest is 120 ms old`. Complete-but-stale against incomplete-but-fresh — head-of-line blocking, visible. Starting a run and navigating away mid-run produced **no console error or warning**, so the interval is released. ESLint caught the first version: the `prefers-reduced-motion` branch called `setState` inside the effect. It was right for a better reason than performance — that decision belongs to the click, not to a synchronisation effect — so it moved to the handler and the effect lost three lines.

**3.1–3.3 — the page.** At 1440 px: three sections in order plus the quiz, every interactive above its own prose, no horizontal scroll. At 375 px: 6 figures exist but only **3 are visible**, one per comparison, with 3 language switches; `scrollWidth` 375 = `innerWidth` 375. Switching one to Rust shows only that pane, labelled "Rust — for comparison — not built here". Quiz: answering marks the option, locks the group, shows the explanation and moves the score to `1 / 6`. All **38** focusable controls on the page are at least 44 px tall. The navigation shows exactly `/` and `/trade` with **neither highlighted** — no change to `AppNav` was needed.
