  **Confirmed, no change needed.** `usePoll` stores its state as `Slot<T> = { url, poll }` and derives what it returns with `slot.url === url ? slot.poll : initialPollState()`. Only the **url** discards the data; `intervalMs` appears solely in the effect's dependency list, so changing it re-arms the timer (and fetches once immediately) while `slot` — and therefore the last good data, `stale` and `updatedAt` — is untouched. No test was added because there is no new pure behaviour to assert: `pollTransition`, which owns the data-keeping rule, is already covered.
